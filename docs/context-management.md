# 上下文管理与执行边界说明

AgentLoop 核心为应用提供可组合的上下文与执行机制。以读取大型日志为例：工具先将原文保存为受控文件，模型接收短预览及引用；需要更多信息时按页回读。预算不足时释放旧结果文本，保留其来源引用。调用方保存的最新任务状态在下一轮重新注入，无需让模型通过摘要重建执行事实。

## 原文归档和按需回读

`ToolOutput` 携带输出文本与原文引用。归档引用记录路径、内容哈希和字符范围；回读检查文件是否变化，并返回下一页位置。对很长的单行 JSON 使用字符分页，普通源码保留行号读取。

已回读内容再次被压缩时复用原始引用，避免把带展示格式的片段反复归档为新证据。摘要只使用已观察的字符范围。归档仍是本地敏感数据，应用负责其权限与生命周期；它不自动脱敏或证明证据完整。

## 动态状态与请求预算

`context_provider` 由应用提供程序维护的当前状态，每轮组装进系统上下文，并与当前工具定义一起纳入预算。动态状态不反复追加到历史，也不依赖模型摘要持久化。

配置 `RequestBudget` 后，根据完整请求估算上下文占用，避免同时受到隐式字符数、消息数阈值的重复压缩。未配置时保留原有保护。估算值不是服务商实际 token 计数。

需要腾出空间时优先处理较旧的工具结果，保护最新工具批次，并保持调用与结果配对。`context_prepared` 事件提供触发原因、淘汰结果数、引用复用数和摘要调用数，便于定位上下文开销。

## 引用、日志索引与进展提示

`ScopedReferences` 为应用已核验的值登记稳定短引用，保留任务范围、类型、来源和父引用。它不自动判断任意日志中的值属于哪个任务，也不提供完整应用状态的跨进程恢复。

日志索引提供有界的时间、文本信号、字面指标和原文位置，显式记录省略数量。错误与完成标签只是文本观察；最大字面耗时不能未经关联就解释为目标请求耗时。

核心对连续相同工具参数及结果给出重复提示，提示不会自动阻止工具或宣告任务结束。语义证据去重、查询覆盖和来源阻塞判定由应用实现。

## 工具和任务退出

`RoundControl` 固定本轮提供的工具集合，执行阶段再次核验。`CallBudget` 提供单调时钟截止时间，外部客户端需要将其连接到传输取消机制；它不能强行中断任意阻塞 handler。

任务结果验收、用户取消、轮次预算及收尾预算分别处理。调用提交工具不等于业务结果已被接受；最后一轮已返回的合法工具调用仍执行，超出预算的下一次模型调用被阻止。命令输出有存储上限，取消和超时保留部分结果并明确其范围。

## 验证与适用范围

本次本地核心测试 191 项通过，覆盖归档回读、请求预算、推理协议回传、引用范围、工具约束及执行控制。测试通过不能替代真实模型任务质量评估。

业务适配层可以在这些机制上实现证据包、检查点、重复证据识别和阻塞退出，但这些策略不属于核心的自动根因判断。模型单步决策实验、特定服务日志采集与业务报告协议不在本次核心提交中。完整参数与示例见 [runtime.md](runtime.md)。
