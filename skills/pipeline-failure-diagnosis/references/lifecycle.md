# 创建、删除与异步生命周期

## 创建或终态超时

沿实际证据核对入口校验、资源选择、下游调用、任务派发、单项执行、回调与状态写回。该顺序是调查方向，实际调用顺序服从对应版本的代码和日志。

- 预检返回库存不足，不证明实际创建请求已发出；核对本次规格、资源池、环境和创建调用。
- API 受理成功，不代表资源创建完成；需要关联 TaskId、执行结果及最终状态。
- 用例等待超时可能发生在尚未完成、下游晚成功或状态未收敛等情形，先区分，不能统一归因为等待时间太短。
- 聚合任务成功，不代表其中每项资源都成功；分别检查单项失败与外层状态。

## 删除与清理

先确定失败阶段：前置查询、删除请求、下游释放、订单处理或异步收敛。清理阶段失败不能改写成后续业务断言失败。

读取成功只证明该读取操作成功，不能排除删除路径独立的参数、权限和业务校验。泛化服务端错误本身不能排除这些可能性。

历史测试标签、曾经为空的依赖列表和资源长期未使用，都不足以证明当前删除安全。诊断只记录状态和建议条件，不执行删除或重放写请求。

## 历史残留与本次失败

有明确残留线索时，沿同一资源的创建、重试和回调历史做有界回溯。分别记录首次失败、后续事件、本次阻塞和未证实的连接。

例如“创建超时”“随后请求发生幂等冲突”“本次清理失败”可以分别是事实；要说第一件事造成第三件事，还需请求、状态或字段转换的证据。不要用时间顺序替代因果证明。

## 后台任务

区分调度触发、主节点或锁判断、派发、单项执行、下游结果和状态提交。进程存活、一次派发成功和某轮顶层成功都不证明持续调度正常。

在相同资源与任务范围内对照多个周期，检查正常无任务跳过、依赖等待、重试与停滞。单个有限日志窗口不能证明无限重试；日志写“释放锁”也不说明记录的总耗时就是取锁等待时间。

## 建议边界

仅对已定位的问题给出具体改动方向与验证条件，区分缓解和根因修复。代码建议需对应实际版本；不以吞错、跳过测试或放宽断言代替修复。重启、变更或重跑均不在本 Skill 的执行范围内。
