# 运行范围、证据关联与覆盖

## 谁提供归属

平台响应提供 Run 与 Job 执行关系；用例输出提供业务请求线索；跨服务日志提供请求改写或异步任务映射。采集程序核验后登记，引用表保存结果，不从字符串形状推断归属。

区分三种编号：工具调用编号配对调用与返回；请求引用定位已登记的请求值；证据编号定位采集材料。它们不能互换。示例中的 `I1`、`E1` 都是合成编号，实际格式服从宿主。

多任务调查分别登记。跨 Job 的同资源记录可作为相关线索；宿主需要显式保存映射及获准的证据归属，不能直接拿另一个 Job 的引用绕过校验。

## 关联强度

| 依据 | 能支持的表述 |
|---|---|
| 完整请求标识，且环境、操作和时间一致 | 同一次请求的观测 |
| 明确的父请求到子请求、任务或消息映射 | 跨服务或异步关联，仍须核验结果 |
| 相同资源和邻近时间 | 相关候选，不能单独证明因果 |
| 相似错误或标识前缀 | 搜索线索，不能确认同一调用 |

脱敏后需要关联的标识使用同一映射表稳定替换，例如同一原请求始终对应 `request-demo-a`。不要把所有请求都替换成同一个值。公开示例用合成数据；运行时向模型提供哪些业务字段，由本次数据策略决定。

## 查询覆盖

记录实际来源、执行位置、时间范围与时区、版本、查询过滤条件、已返回页和截断状态。只检查某个副本或最后一页，不能声称检查了整个服务。

可用 `observed`、`not_found`、`not_queried`、`access_denied`、`expired`、`query_failed` 表达来源状态；名称可由宿主协议调整。`not_found` 必须有实际查询范围；登录页、权限错误和超时都不是空日志。

从配置或已授权发现结果选择主机、服务与文件。服务写入文件时，标准输出未命中不能证明不存在；需要相关历史而日志轮转已不可用时，写明保留范围。不得默认扩大到全盘、全部主机或所有环境。

记录实际执行过的查询与工具返回；命令模板和建议单独标为未执行。报告中不能暴露认证参数或链接票据。

多个实例读取共享文件时，核对实际写入者和记录标识；同一行被重复返回不能算作多个独立来源的佐证。

## 测试程序尚未启动

外层“任务启动失败”需要沿实际执行入口找到重定向输出和首个错误。配置生成、进程启动、负载运行和结果断言是不同阶段；负载未启动不能报成被测存储性能不达标。

若首个错误提示无法写文件，在获准的测试机和工作目录范围内核对容量、inode 与权限等相关证据。没有相应查询能力就列出所缺信息；不以清理文件、重跑或修改断言作为默认诊断动作。

## 字段值与来源

字段争议先建立对照：组件、事件时间、对象与完整字段路径、JSON 类型、观察状态、证据位置和代码版本。

| 状态 | 判定条件 |
|---|---|
| `value` | 已取得的来源明确包含该键且值非 null；0、false 和空字符串也是值 |
| `null` | 已取得的来源明确含该键，原值为 JSON null，而非采集器填充的默认值 |
| `missing` | 已取得包含该字段应属范围的完整对象，其中没有该键 |
| `unavailable` | 对象未取得、解析失败、被截断或被投影，无法判定 |

投影中明确返回的字段仍可记录其观察值；只有判断未出现的字段是否 missing，才需要证明对应对象完整。`dict.get()` 返回 None 不区分 missing 和 null；脱敏或投影未显示字段也不证明源数据缺失。不要用 `value or fallback` 混淆合法零值。不同接口的同名字段不能自动等同，语义需匹配版本的接口约定或赋值代码支持。
